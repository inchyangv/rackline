## 적용한 결정 ID·버전 / 가정 / OPEN 항목

- 적용: R2-D02(API ready·eth_call·native accepted·consumed 독립 — 0002 trigger + lifecycle이 status만 이동), R2-D03(signer/fallback job kind 없음, 테스트로 고정), R2-D07(queue는 경제 효과에 관여하지 않음; dedup은 ledger unique key), PIVOT §8.3(failed row 영구 skip 금지 → DEAD는 사유·actor 있는 resume만), GPU-016 `hcg_lease_job`/`jobs`/`outbox`/`audit_log` 재사용.
- 가정: 스키마 `FAILED` 상태는 미사용(transient = PENDING+next_run_at, terminal/소진 = DEAD) — `hcg_lease_job`이 PENDING/LEASED만 lease하기 때문. 후보 SELECT + 함수 호출 2단계(함수 자체가 원자적이므로 경쟁 안전).
- 스키마 gap(신규 migration 금지로 코드 우회): (1) `jobs`에 fencing token 컬럼이 없어 `(leased_by, attempt)`로 대체 — 충분하나 GPU-016 후속에서 `lease_token` 컬럼 고려; (2) `proof_requests`에 next job 링크 없음 — `job_key(kind, id)` semantic key로 연결; (3) `outbox` 실패 사유 컬럼 없음 — attempt만 증가.
- OPEN: 없음(이 티켓). 실제 proof service/SDK 연결·attestation 대기·submission tx는 GPU-079, 공개 testnet은 GPU-080.
