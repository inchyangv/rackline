## 적용한 결정 ID·버전 / 가정 / OPEN 항목

- 적용: docs/gpu/accounting.md §2–§3(GPU-012 SPEC v1): ACT/365 단리·원금에만·정확한 분자·segment 전진 적용·waterfall; AR-01/02/03/04 정정값; R2-D06(단일 계산 원천), R2-D07(원장은 증거에 무의존 — proof 장애 중에도 `allocate` 가능); TS-O05(자본화 기본 off).
- **rounding 정책**: 분자 `Σ principal×rateBps×seconds`는 절대 반올림하지 않는다. 표시/청구 단위는 `floor(accum/DENOM)`; 지급은 `units×DENOM`만 차감하므로 분수 잔여(0~DENOM−1)는 분자에 남아 다음 accrual에서 완성된다. 결과는 accrual 횟수·부분 상환 횟수와 독립(AC-03: 365회 일별 accrual과 1회 accrual의 **분자가 동일**함을 assert). 차주는 1단위 미만을 청구받지 않는다(floor = lender-conservative).
- 가정: `accrue`/`setRate`/`allocate`는 `block.timestamp` 기준(외부 시각 입력 없음). 미래 rate 예약은 지원하지 않으므로 pending 기간은 항상 현재 segment 단일 rate → view가 exact. rate 변경 미지원 정책은 아니고 **소급 금지 구간 checkpoint**로 지원.
- 가정: writer = manager/router 계약(allowlist). state 전이는 GPU-036/041의 manager가 `setState`로 기록(원장은 상태 머신을 검증하지 않음).
- OPEN: 상각 후 계약상 연체이자(TS-O09)는 이 원장 밖(freeze 후 비발생). maturity 경과 시 자동 처리 없음(GPU-041).
