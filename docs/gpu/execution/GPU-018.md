## 적용한 결정 ID·버전 / 가정 / OPEN 항목

- 적용: R2-D03/D04(세션·로그인 서명은 보조 경로; source 사실·verified 상태 생성 경로 없음), R2-D12(LOCAL_MOCK manifest ≠ native; production 거부), GPU-013 §1–§2(역할, 서명 목적 분리, epoch), GPU-001(production API 키 없음 재확인), GPU-011 §11(ErrorCode: UNAUTHENTICATED/FORBIDDEN_SCOPE/NOT_FOUND/VALIDATION/UNSUPPORTED_SOURCE/PROFILE_MISMATCH/RATE_LIMITED/UPSTREAM_UNAVAILABLE).
- 결정: 로그인 도메인을 온체인 도메인과 **분리**(salt 기반, verifyingContract 없음). 이유: API 로그인 서명이 온체인 WALLET_LINK 소비로 재생되면 사용자가 인지하지 못한 온체인 상태 변화를 만들 수 있음. 온체인 링크는 GPU-030 `AuthorizationVerifier`용 별도 서명.
- 결정: bearer-only(쿠키 미사용) → CSRF double-submit 불필요; CORS는 설정 allowlist.
- 가정: in-memory challenge/role/ownership store는 단일 프로세스용; GPU-016/017의 DB 구현이 같은 Protocol로 교체. rate limiter도 프로세스 로컬(다중 인스턴스는 GPU-053/059).
- OPEN: 실제 provider OAuth/token 방식은 파트너 자료(GPU-004/005) 필요 → `credentialRef`만 저장, 값 해석은 서버 내부 `SecretStore`.
