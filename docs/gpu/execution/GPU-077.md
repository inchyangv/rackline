## 적용한 결정 ID·버전 / 가정 / OPEN 항목

- 적용: R2-D05(source 사건 ≠ 매출/현금/권리), R2-D06(과거 payout/anchor ≠ 새 채권; stale snapshot 재발행 불가), R2-D12(TEST_ONLY ≠ production provider); GPU-076 §4(이벤트 의미·emitter 역할), §5(issuer authority, revision 단조, settlementSeq replay 방지), §6(checkpoint), EC-O01~O03은 여전히 OPEN(파트너 의존).
- 가정: source 계약은 destination `GpuTypes`에 의존하지 않고 plain `bytes32`를 쓴다(ABI 동일). `dueAt`은 CLAIMED 값. rebase 토큰은 잔액 drift로만 탐지(`recordDirectDeposit`가 양의 drift를 unattributed로 흡수; 음의 drift는 settle 측정에 영향 없음).
- 설계 메모: `PayoutReceived(obligationRef=0)`은 등록 payer의 미귀속 정산(fixture 정의)이고, 비-payer 입금은 별도 `UnattributedDeposit`(registry에 revenue meaning으로 등록하지 않음). unattributed 자금은 on-chain에서 매출로 재분류하는 함수가 없다(환불은 `withdraw`).
- OPEN(이 티켓 밖): 실제 파트너 source ABI/escrow 의미(GPU-004/005/008), 공개 testnet 배포·native 검증(GPU-080), GPU-037 escrow/waterfall 조합.
