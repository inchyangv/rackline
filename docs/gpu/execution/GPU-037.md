## 적용한 결정 ID·버전 / 가정 / OPEN 항목

- 적용: R2-D07 / SR-D03(sweep은 leg 2, debt는 leg 5에서만), SR-D08(settlementId 연결), R2-D09(Writability·cross-chain 없음), R2-D04/D05(claim 성공·registry 항목은 E2 증거가 아님), GPU-013 §3–§4(release = servicer 승인 + treasury 실행 + debt 0 + 대사 window + refund 없음; registry gate), PIVOT §5.2 waterfall 순서, GPU-077 측정 delta·unattributed 분리.
- 우선순위 규칙: facility 배열 순 seniority, 각 facility의 `target`(UNDERWRITER가 version별로 선언한 sweep 상한; 주장값)까지. pro-rata 미채택(단순·검증 용이). 반올림: 수익자 floor, 나머지 residual.
- 가정: (1) LOCAL에서는 `CONTROL`이 실제 ControlRegistry(동일 체인). 실제 source chain 배포에서는 SERVICER/TREASURY가 유지하는 mirror 계약이 같은 view를 제공해야 하며 mirror는 설정이지 E2 증거가 아니다(GPU-038/040 범위). (2) `SourceEscrow.withdraw`가 unattributed bucket을 먼저 차감하는 GPU-077 동작은 이 계약이 shadow 회계로 보정한다 — GPU-077에 개선 메모(범위 밖, 미수정). (3) `_hasUnsweptPayout`은 전체 payout 순회(O(n)); 파일럿 규모에서 허용, GPU-059 성능 한도에서 재검토.
- OPEN: 없음(이 티켓). reserve의 debt 충당·first-loss 사용은 GPU-041, 실제 settlement leg(bridge/환전)는 GPU-040/SR-O03.
